## 1. Objective

Ввести явный и тестируемый runtime transition для HTTP 401:

```text
authenticated/ready → authentication-required
```

При переходе: очистить legacy stored token и token input, сохранить non-secret
JSON edit buffers, показать безопасное сообщение, не выполнять automatic
retry/reload; после явного Save — ровно один refresh.

## 2. Business / security value

401 без явного auth-state оставлял token input и storage в рассинхроне и мог
запускать refresh loop при наборе нового токена. Контракт устраняет утечку
secret material в transition payload, запрещает structural lookalike errors и
сохраняет незакоммиченные edit buffers редактора.

## 10. State contract

Module: `apps/admin/src/auth-failure-state.ts` (pure; imports only `ApiClientError`).

Exports:

- `AdminAuthState` (`ready` | `authentication-required` + `reason: "http-401"`)
- `AuthFailureTransition` (exact fields/literals)
- `READY_AUTH_STATE` frozen `{ status: "ready" }`
- `authFailureTransition(error)` → frozen transition or `null`

No circular import: `api.ts` does not import auth-failure-state.

## 11. Transition semantics

Exact predicate:

```text
error instanceof ApiClientError
AND code === "AUTHENTICATION_REQUIRED"
AND status === 401
```

Otherwise `null` (403/409/422/5xx/generic/structural/null/undefined).

Frozen transition includes `nextTokenInput: ""`, `clearLegacyToken: true`,
`preserveEditBuffer: true`, `retry: "manual"`, message
`Требуется повторная авторизация`. No token/URL/payload/callback fields.

## 12. Adapter clear

```ts
clear() {
  sessionStorage.removeItem(LEGACY_TOKEN_STORAGE_KEY);
}
```

`removeItem` only; no read-before-clear; no fallback/catch/log; errors propagate;
key remains private; deprecation comments preserved.

## 13. App integration

- `authState` initialized to `READY_AUTH_STATE`
- single `handleRequestError` used by refresh / saveCurrent / runPublish
- 401 path: `clear()` + clear input + set auth-required + safe status; no buffer setters; no refresh/reload/timer
- effect: `if (legacyTokenAdapter.read()) void refresh()` deps `[refresh]` only
- `applyToken`: write → ready → `Токен сохранён` → exactly one `void refresh()`
- status element: `role="status"` + `data-auth-state={authState.status}`

## 14. Buffer preservation

401 handler never calls `setCatalogJson` / `setMapJson` / `setSiteJson` /
`setOffersJson` / `setTab`. Non-401 path also leaves buffers untouched.

## 15. Reload-loop prevention

Removed `tokenInput` from effect dependencies. Typing a replacement token
issues zero requests; Save triggers one explicit refresh.

## 16. Re-auth Save flow

1. User types new token (no network)
2. Save → adapter.write → READY_AUTH_STATE → status `Токен сохранён` → one refresh
3. Successful refresh restores buffers from server; failed non-401 uses legacy message fallback
