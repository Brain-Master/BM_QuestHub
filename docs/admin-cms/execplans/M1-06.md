## 12. Normalization rules

- Strings: trim; empty → invalid; max 160 UTF-16 units; sourceStatus max 64;
  no truncate; no locale transform.
- Required identity/title invalid → skip row.
- Optional invalid → `null`.
- Numbers: no string coercion; enrolled integer ≥0; maxCapacity integer >0;
  `available = max(capacity - enrolled, 0)` when both present else `null`.

## 13. Status rules

- Course: `true`→active, `false`→inactive, else unknown.
- Venue: `true`→listed, `false`→hidden, else unknown.
- Offer availability precedence: archived → full → available → unknown.
- Offer `sourceStatus`: `scheduleCard.status` then `sheetStatus` then null;
  not used as availability.

## 14. Relationship counts

- World `courseCount`: Map over readable courses by `worldId` — O(worlds+courses).
- Course `offerCount`: Map over readable offers by `courseId` — O(courses+offers).
- Venue `offerCount`: Map over readable offers by `venueId` — O(venues+offers).
- No nested `filter` cross-products.

## 15. Collection status semantics

Implemented per Task Packet §16 for catalog/map/site/manifest/offers
(`ready` / `empty` / `unavailable` / `malformed`).

## 16. Complexity analysis

Offer flatten O(offer rows); relationship counts O(entities + offers);
no quadratic entity×entity loops.
