## 2. Objective / business / security value

Добавить к legacy admin API client минимальный безопасный observability
contract: один safe outbound `x-request-id` на operation, стабильное operation
name (не raw URL/path), ровно один frozen terminal event после settlement и

без body, token, headers, URL, path, error text, stack, cause, payload,
response или snapshot data. Optional observer/clock/request-ID factory — per
call; их failures изолированы от исходного result/error.

## 5. Current request lifecycle

Pre-M1-11 inventory (`api.ts`):

1. `loadSnapshots` → GET `/snapshots` via query (no body) → `parseSnapshotsBundle`.
2. `saveSnapshot(type)` → PUT envelope `{ data, path: /snapshots/<type> }`.
3. `publishContent(tier)` → POST `{ path: /sync/hot|/sync/cold }`.
4. Shared `request()`: content-type + `x-content-token`; 15s timeout; manual
   cancel; stable `ApiClientErrorCode`; inbound safe correlation from
   `x-request-id` then `x-correlation-id`; non-2xx body unread; JSON parse on
   success only.

M1-11 adds outbound `x-request-id` and optional terminal observer only.

## 7. Exact event schema

```ts
Readonly<{
  requestId: string;
  operation: ApiOperation;
  durationMs: number;
  outcome: ApiRequestOutcome;
  httpStatus: number | null;
}>
```

Exact key order as listed. Forbidden properties include method/path/url/query/
headers/body/payload/data/token/authorization/correlationId/message/error/
stack/cause/response/issues/raw/timestamp/startedAt/endedAt.

`httpStatus` retained only for `http_error` with integer 100..599; otherwise
`null`.

## 8. Request-ID and duration policies

- Sanitizer: `^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$`; no trim/coercion; reject
  secret-like substrings; rejected values never retained.
- Custom safe factory value used exactly; thrown/unsafe custom → fallback UUID;
  unavailable/unsafe default → `Error("Unable to create API request ID")`
  before fetch.
- Duration: `Math.round(endedAt - startedAt)`; negative/non-finite → `0`;
  integer ≥ 0.

## 9. Observer / factory / clock isolation

Per-call `ApiObservabilityOptions`: `onObservation?`, `now?`,
`createRequestId?`. Observer return ignored. Factory/clock/observer exceptions
never replace the original API result or error. Exactly one terminal emit after
request cleanup (not dual catch+finally).

## 17. M1-11-R1 corrective note

Review of draft PR #7 discovered a MAJOR clock-isolation mismatch in private
`readNow` inside `apps/admin/src/api.ts`:

- custom thrown/non-finite clocks fell back to unguarded `performance.now()`
  instead of safe timestamp `0`;
- the default clock itself was outside `try/catch`, so a throwing
  `performance.now()` could prevent fetch start, replace a successful result,
  replace the original request error, or skip terminal observation;
- original Q29 proved fallback-to-default behavior (operation preservation
  while the real default clock stayed healthy) and did **not** assert
  `durationMs === 0` or force default-clock failure on success/HTTP error.

Correction scope (authoritative detail in `docs/admin-cms/execplans/M1-11-R1.md`):

- only private `readNow` selection/fallback semantics;
- only strengthening of existing Q29 evidence;
- event schema, operation/outcome taxonomy, outbound request-ID pipeline,
  redaction, and M1-10 inbound correlation remain unchanged.
