## 14. Boundary design

- Export frozen `CURRENT_SNAPSHOT_VERSIONS`.
- Extend `SnapshotBundleValidationExpected` with `literal 1`, `literal 2`,
  `string`, `array`.
- Private field contracts per root; `validateDocumentFields` then
  `validateSnapshotDocuments` after successful root checks.
- Success returns original input by identity; no clone/strip/normalize;
  no filesystem/network.

## 15. Diagnostic order / redaction

Document order catalog → map → site → manifest → offers. Field order as §11.
No `received` / `value` / `input` / `details` / `cause` on issues. Error message
remains bounded generic `"Snapshot bundle failed validation"`.

## 16. Fixture migration

Valid synthetic documents carry required fields + `fixtureKind` + metadata
`synthetic-generated-at` / `synthetic-source` / `synthetic-content-hash`.
Nullable fixture keeps manifest/offers `null`. Invalid fixtures remain six
with same IDs; non-target roots are contract-compatible (compact, no
fixtureKind) so first issues stay intentional.
