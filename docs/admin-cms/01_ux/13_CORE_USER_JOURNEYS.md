# Ключевые пользовательские сценарии

Каждый сценарий фиксирует цель, шаги, ожидаемое ощущение, ошибки и критерий завершения.

# J1. Первый вход

1. Пользователь открывает `/admin`.
2. Система проверяет server session.
3. При отсутствии сессии показывает login.
4. После входа получает permissions.
5. Dashboard показывает blockers, drafts и последний release.
6. Production явно обозначен.

Ошибки:

- expired session → повторный вход без потери local buffer;
- disabled account → ясный экран;
- no permissions → объяснение и contact path.

**Done:** пользователь без инструкции находит `Расписание`.

# J2. Изменить цену одного формата

1. Открыть `Расписание`.
2. Найти школу/курс и ограничить даты.
3. Открыть смену.
4. Выбрать OfferFormat.
5. Изменить цену.
6. Увидеть before/after.
7. Нажать `Сохранить черновик`.
8. Получить новую revision.
9. Открыть preview.
10. Publisher публикует hot release.
11. Verification подтверждает цену.

Ошибки:

- отрицательная цена → inline error;
- revision conflict → comparison dialog;
- сеть пропала → данные остаются;
- publish blocked → ссылка на проблему.

# J3. Создать смену копированием

1. Открыть существующую смену.
2. `Создать копию`.
3. UI показывает, что копируется.
4. Не копируются enrolled и external codes по умолчанию.
5. Пользователь задаёт новые даты.
6. Система проверяет пересечения.
7. Создаётся новый immutable ID.
8. Пользователь редактирует форматы и сохраняет draft.

# J4. Создать курс

1. `Курсы` → `Новый курс`.
2. Выбрать World.
3. Ввести название; slug предложен автоматически.
4. Заполнить карточку, hero, историю, навыки, результат и подход.
5. Completion indicator показывает прогресс.
6. Загрузить media.
7. Сохранить draft.
8. Открыть preview карточки и detail page.
9. Исправить warnings.
10. Передать Publisher.

# J5. Добавить корпус

1. Venue → `Корпуса` → `Добавить`.
2. Ввести адрес и выбрать результат поиска.
3. Проверить marker.
4. Указать метро, район и инструкции.
5. Загрузить локальные медиа.
6. Сохранить.
7. Система проверяет похожие адреса.

# J6. Массово обновить расписание

1. Отфильтровать список.
2. Выбрать строки.
3. `Изменить`.
4. Dialog показывает количество объектов.
5. Для каждого поля есть checkbox `Изменить это поле`.
6. Preview diff.
7. Batch command выполняется с idempotency key.
8. Возвращается per-item result.
9. Ошибочные строки не скрываются.

Запрещено молча заменять пустыми значениями и silently skip conflict.

# J7. Заменить hero

1. Course → Media.
2. Hero slot показывает asset и usages.
3. `Заменить`.
4. Проверка type/size.
5. Crop 16:9 и focal point.
6. Preview desktop/mobile.
7. Processing timeline.
8. Создать draft relation.
9. Старый asset остаётся в history.

# J8. Опубликовать релиз

1. Открыть `Публикация`.
2. Изменения сгруппированы по типам.
3. Blockers сверху.
4. Publisher открывает diff.
5. Запускает preview compile.
6. Проверяет затронутые страницы.
7. Вводит comment.
8. Подтверждает публикацию.
9. Job показывает фазы.
10. Verification проверяет сайт.
11. Success показывает release ID, ссылки и rollback.

# J9. Исправить blocker

1. Validation возвращает список.
2. Пользователь открывает проблему из Publication Center.
3. Нужное поле получает focus.
4. Исправление сохраняется новой revision.
5. Scope и validation пересчитываются.

Пользователь не ищет объект по техническому ID вручную.

# J10. Rollback

1. Открыть текущий release.
2. `Откатить`.
3. Система показывает current и target release.
4. Показывает исчезающие изменения.
5. Требует comment.
6. Pointer переключается атомарно.
7. Verification подтверждает старый release.
8. Drafts и новые revisions не удаляются.

# J11. Импорт Google Sheets

1. Выбрать источник.
2. Система читает без записи.
3. Показывает mapping, новые объекты, updates и conflicts.
4. Пользователь решает conflicts.
5. Dry-run validation.
6. Confirm.
7. Import job создаёт revisions.
8. Автопубликации нет.
9. Доступен report и rollback import batch.

# J12. Конфликт редактирования

1. A открывает revision 5.
2. B сохраняет revision 6.
3. A сохраняет старую версию.
4. Сервер возвращает conflict.
5. UI сохраняет изменения A.
6. Показывает local/server field diff.
7. A выбирает merge или reload.
8. Merge сохраняется против revision 6.

# J13. Потеря сети

1. Форма сохраняет local recovery buffer.
2. Banner показывает `Нет соединения`.
3. Publish disabled с причиной.
4. После восстановления запускается retry и revision check.

# J14. Архивирование

1. `Ещё` → `Архивировать`.
2. Dialog показывает usages.
3. Активные dependencies блокируют действие или требуют resolution.
4. Пользователь вводит reason.
5. Entity получает `archived`.
6. Public effect происходит только после release.
