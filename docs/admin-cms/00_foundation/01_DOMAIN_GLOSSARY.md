# Доменная модель и канонический словарь

## 1. Правило терминологии

В коде, API, БД, UI и документации одно понятие должно иметь одно основное имя. Допустимые пользовательские синонимы фиксируются отдельно. Нельзя использовать `group`, `shift`, `camp`, `session` и `offer` как взаимозаменяемые слова без явного определения.

## 2. Основные сущности

### World / Мир

Маркетинговая и тематическая группа курсов.

Примеры:

- КиберРитм;
- Мехвариум;
- Minecraft.

Канонические свойства:

- стабильный `id`;
- человекочитаемый `slug`;
- название;
- краткое описание;
- tagline;
- pitch;
- highlights;
- theme key;
- icon key;
- hero media;
- статус.

Связи:

```text
World 1 ─── N Course
```

### Course / Курс

Повторно используемая образовательная программа, независимая от конкретной даты и площадки.

Канонические свойства:

- стабильный `id`;
- `worldId`;
- slug;
- title;
- tagline;
- catalog tagline;
- возрастной диапазон;
- формат продукта;
- навыки;
- история;
- результат для ребёнка;
- подход;
- базовые медиа;
- статус публикации.

Нельзя хранить в Course цену и точное расписание конкретной смены.

### Venue / Площадка

Организация или логическая площадка BrainMaster.

Пример: школа или центр, который может иметь один либо несколько корпусов.

### VenueCampus / Корпус

Физическое место проведения:

- адрес;
- координаты;
- метро;
- район;
- инструкции прохода;
- заметка о входе;
- контактная заметка;
- локальные медиа.

Разделение `Venue` и `VenueCampus` необходимо для многокорпусных организаций.

### Shift / Смена

Конкретный запуск курса в определённом корпусе и диапазоне дат.

Свойства:

- immutable `id` в формате UUID/ULID;
- `courseId`;
- `venueCampusId`;
- start date;
- end date;
- статус набора;
- преподаватель;
- общая вместимость;
- описание-override;
- адрес-override только при реальной необходимости;
- архивность.

Составная строка вида `course:venue:start:end` может быть `externalKey`, но не первичным идентификатором.

### OfferFormat / Формат участия

Один доступный вариант участия внутри смены.

Примеры:

- полный день;
- полдня;
- четырёхдневный интенсив;
- марафон.

Свойства:

- `shiftId`;
- время начала и окончания;
- цена;
- вместимость;
- количество записанных;
- возраст;
- тип формата;
- канал регистрации;
- внешняя ссылка;
- waitlist policy.

```text
Shift 1 ─── N OfferFormat
```

### MediaAsset / Медиаобъект

Стабильная запись о загруженном исходнике и его производных вариантах.

Свойства:

- immutable id;
- source object;
- mime type;
- dimensions/duration;
- checksum;
- processing status;
- alt text;
- caption;
- focal point;
- variants;
- owner entity;
- author and timestamps.

Путь в S3 не является идентичностью медиа.

### Draft / Черновик

Состояние сущности, доступное редакторам, но не влияющее на публичный сайт.

### Revision / Ревизия

Неизменяемая версия одной сущности после сохранения.

### Release / Релиз

Атомарный набор опубликованных ревизий и generated artifacts.

### Snapshot / Снимок

Сгенерированный JSON-контракт для публичного сайта. Snapshot является output компилятора, а не редактируемым документом.

### PublicationJob / Задача публикации

Отслеживаемая серверная операция:

```text
queued → validating → compiling → uploading → activating → verifying → succeeded
                                                └──────────→ failed
```

### AuditEvent / Событие аудита

Неизменяемая запись о значимом действии:

- actor;
- action;
- entity;
- previous revision;
- new revision;
- request/session context;
- timestamp;
- result;
- reason/comment.

## 3. Статусы

### Статус сущности

```text
draft
ready
published
archived
```

`ready` означает, что сущность прошла блокирующие проверки, но ещё не опубликована.

### Статус смены

```text
draft
open
sold_out
closed
cancelled
archived
```

Пользовательские подписи:

| Код | UI |
|---|---|
| `draft` | Черновик |
| `open` | Идёт набор |
| `sold_out` | Мест нет |
| `closed` | Набор закрыт |
| `cancelled` | Отменена |
| `archived` | В архиве |

### Статус сохранения формы

```text
clean
dirty
saving
saved
save_failed
conflict
```

### Статус публикации

```text
not_published
queued
validating
blocked
publishing
verifying
published
failed
rolled_back
```

## 4. Владение полями

Каждое поле должно иметь одного владельца.

| Данные | Владелец |
|---|---|
| базовое название курса | Course |
| адрес корпуса | VenueCampus |
| дата смены | Shift |
| время и цена | OfferFormat |
| записано участников | интеграция или OfferFormat read model |
| hero курса | Course media relation |
| локальная фотография площадки | VenueCampus media relation |
| override адреса для одной смены | Shift |
| generatedAt/contentHash | Snapshot compiler |

Если поле продублировано, UI должен объяснять приоритет. Предпочтительно заменить дублирование relation или явным override.

## 5. Текущие таблицы → целевые сущности

### Cold Content

| Лист | Целевая сущность |
|---|---|
| Миры | World |
| Площадки | Venue + VenueCampus |
| Курсы | Course |

### Hot Content

| Лист | Целевая сущность |
|---|---|
| Группы | Shift |
| Форматы | OfferFormat |

## 6. Override-поля

Override допускается только когда значение действительно отличается для одной конкретной сущности.

Правила:

- поле называется с суффиксом `Override`;
- UI по умолчанию показывает наследуемое значение;
- включение override является отдельным действием;
- рядом показывается источник базового значения;
- сброс override возвращает наследование;
- override включается в audit diff;
- массовое редактирование не включает override без явного выбора.

## 7. Идентификаторы

### Внутренний ID

- UUID/ULID;
- не меняется;
- не зависит от названия, даты, адреса;
- используется в БД и API.

### Slug

- человекочитаемый;
- уникальный в своём namespace;
- меняется редко;
- после публикации изменение требует redirect/alias policy;
- генерируется из названия, но редактируется явно.

### External key

- используется для миграции или внешней интеграции;
- может сохранять старый `shift_group_id`;
- не является primary key.

## 8. Запрещённые размытые термины

Без уточнения нельзя использовать:

- «контент» вместо конкретной сущности;
- «группа» вместо Shift;
- «формат» без указания Course format или OfferFormat;
- «сохранено» в значении «опубликовано»;
- «удалено» в значении «архивировано»;
- «синхронизация» без указания источника и назначения;
- «активно» без указания статуса;
- «места» без указания capacity/enrolled/available.

## 9. Инварианты

1. Course всегда принадлежит существующему World.
2. Shift всегда ссылается на существующие Course и VenueCampus.
3. OfferFormat всегда принадлежит Shift.
4. `startDate <= endDate`.
5. `startTime < endTime`.
6. `price >= 0`; нулевая цена имеет явный смысл, а не используется как скрытый фильтр.
7. `enrolled >= 0`.
8. `capacity >= enrolled`, либо система показывает подтверждённое исключение.
9. Published сущность имеет revision и audit trail.
10. Snapshot никогда не редактируется вручную через продуктовый UI.
11. Release активируется только после полной загрузки и проверки всех обязательных artifacts.
12. Архивирование не нарушает исторические release и audit records.
