# Контекст рекламной кампании: лагеря-интенсивы

**Назначение документа:** синхронизация маркетинга, школ и контента сайта-агрегатора на период запуска.

## Параметры кампании (заполнить фактами)

| Поле | Значение (черновик) |
|------|---------------------|
| Продукт | Каникулярные **интенсивы** (5 дней, ядро инженерного блока; уточнять по площадке полный день) |
| Площадки | Минимум **5** разных школ/баз |
| Временной охват | **Последняя неделя мая** и **всё лето** (перечислить конкретные окна смен по площадкам в таблице-источнике правды) |
| Главный канал к родителю | Школа (рассылки, чаты) → **ссылка в школьный скоуп** агрегатора |
| Дополнительный канал | [VK](https://vk.com/brainMaster), таргет (если используется) — **UTM** на площадку и кампанию |

## Что должно быть готово на сайте к старту трафика

1. **Карточки всех квестов**, которые рекламируются (минимум пять интенсивов из [Продукты-и-каталог-квестов.md](Продукты-и-каталог-квестов.md)), без устаревших цен и дат.  
2. **Каждая площадка кампании**: адрес, метро, доступные смены, состав дня (ядро BM + блок школы), ссылка/инструкция записи.  
3. **Общая страница** FAQ: безопасность (пайка и т.д.), что взять с собой, возвраты/переносы (по фактической политике школы и BM).  
4. **Школьные скоупы** (поддомен или путь со slug) для школ с кампанией — с кнопкой «весь каталог».  
5. **Захват заявок** (см. [Управление-заявками-и-источник-данных.md](Управление-заявками-и-источник-данных.md)): хотя бы форма «остались вопросы» или логирование кликов до mos.ru.

## Риски кампании без агрегатора

- Разные формулировки в чатах школ → **недоверие** и перегруз поддержки.  
- Родитель сравнивает цены площадок без объяснения пакета → **отказ**.  
- Нет единой точки для **аналитики** по переходам из рекламы.

## Следующий шаг после утверждения дат

Свести **одну таблицу** (Google Sheets / Notion / БД): площадка × квест × даты смен × цена × ссылка mos.ru × UTM для скоупа школы.
