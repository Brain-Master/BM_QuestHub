## Обновление: что действительно проверено

Источник: `apps/web/content/annual-mos-refresh.generated.json`, строгая проекция
публичного API без cookies, контактов, токенов и текстов upstream-ошибок.
Discovery: поиск только для первоначального разрешения ID, затем точный GET
`/pgu2/activity/api/groups/{cardId}` с проверкой `circle.number` и `group.number`.
Регулярное обновление **не использует поиск**, не суммирует соседние группы.

Первоначально успешно разрешены 43/51 группы. Следующий реальный запуск нового
локального pipeline прочитал текущий опубликованный S3 snapshot и обновил 42/43
разрешённых карточек; К4956-26 получила timeout, сохранены предыдущие значения
и время. Итого попытка 42/51, `ok:false`, восемь identity errors + один timeout.
Это доказательство read-only чтения источников, не автоматической production работы.

Защита нового pipeline:

1. Перед Sheets импортом проверяет источник, ревизию, ID и корпус уже опубликованных
   annual rows. Неизвестная новая годовая группа останавливает импорт, а не теряется.
2. Восстанавливает более свежие факты того же источника. Такая же защита есть при
   прямом запуске компилятора, не только в GitHub workflow.
3. Проверяет каждый ответ отдельно. Ошибка, смена адреса/организации, невалидные
   диапазоны или исчезнувшее известное поле сохраняют всю последнюю корректную
   карточку без продвижения времени успешной проверки.
4. Валидные обновления могут быть опубликованы вместе с явно помеченными старыми
   сведениями. Частичная попытка даёт отчёт и failed coverage check после такой
   публикации; не выдаётся за успешное обновление всех групп.
5. Hot workflow сериализован; cold не пишет hot schedule. Регулярный запуск
   использует существующий finalizer/таймер, без дополнительного cron.

Production до выпуска остаётся старым: годовые группы из CSV не подключены к
новому механизму. Проверенный прежний run `a28cd6dd-54df-4ea8-91e4-9a0ec668d884`
завершился 2026-09-09T03:04:36Z с 23 ошибками на 23 старых URL, 0 обновлений.
`idle` и время попытки не означают успешную синхронизацию. Эти 23 URL относятся
к прежним интенсивам; их сбои сохранены отдельно от нового annual coverage.
Доступ к API управления YCF в текущей среде несколько раз завершился timeout,
включая TLS к официальному endpoint. Новая версия finalizer не развёрнута.
