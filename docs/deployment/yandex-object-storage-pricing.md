# Yandex Object Storage — тарифы (оценка для Quest Hub)

> **Legacy / alternative.** See [timeweb-object-storage-pricing.md](./timeweb-object-storage-pricing.md) for the current provider.

**Дата сверки:** 2026-05-19. Актуальные цифры в рублях меняются — перед продакшеном проверьте [прайс Object Storage](https://cloud.yandex.ru/docs/storage/pricing) и [калькулятор](https://yandex.cloud/ru/prices?state=83e1258e152c#calculator).

## Бесплатные лимиты (Standard, регион Россия)

| Статья | Лимит в месяц |
|--------|----------------|
| Хранение | первый **1 ГБ** не тарифицируется |
| PUT / POST / PATCH / LIST | первые **10 000** операций |
| GET / HEAD / OPTIONS | первые **100 000** операций |
| Исходящий трафик в интернет | первые **100 ГБ** |

Входящий трафик из интернета и трафик между сервисами Yandex Cloud в Object Storage **не тарифицируется**. DELETE не тарифицируется.

Источник: [правила тарификации Object Storage](https://cloud.yandex.ru/docs/storage/pricing).

## Платные статьи (что обычно «съедает» бюджет)

1. **Хранение** — ГБ×месяц (класс **Standard** для публичного CDN; Cold/Ice не подходят для горячей раздачи).
2. **Исходящий трафик** — после 100 ГБ/мес; при full CDN через [Yandex CDN](https://cloud.yandex.ru/docs/cdn/pricing) трафик к пользователям часто идёт с CDN (отдельный прайс на исходящий трафик CDN).
3. **Операции** — редко заметны при типичном сайте, если не миллионы GET; деплой `aws s3 sync` даёт в основном PUT.

С **20.04.2026** тарифицируется S3 Inventory (для Quest Hub не требуется).

## Оценка для BrainMaster Quest Hub

Ориентиры объёма (уточните `du` после первой выкладки):

| Префикс | Содержимое | Порядок объёма |
|---------|------------|----------------|
| `data/` | JSON snapshots + `data/v2/*` | единицы–десятки МБ |
| `media/` | WebP/PNG квестов | десятки–сотни МБ |
| корень / `www/` | `apps/web/out` (если full CDN) | десятки–сотни МБ |

### Сценарий A: только `data/` + `media/` на Storage, HTML на Timeweb

- Хранение: часто **≤ 1 ГБ** → в пределах free tier по ГБ.
- Трафик: медиа и JSON с `storage.yandexcloud.net` или через CDN; при умеренной посещаемости часто **< 100 ГБ/мес**.
- Операции: CI build (несколько GET JSON) + деплой sync — **далеко от лимитов** free tier.
- **Ожидаемый порядок:** 0–несколько сотен ₽/мес при малом трафике; основной риск — рост трафика, не хранение.

### Сценарий B: full CDN (статика + медиа + JSON в бакете + Yandex CDN)

- Хранение: как в A, возможно +50–200 МБ статики.
- Трафик: **основная статья** — CDN egress + запросы к origin при промахах кэша.
- CDN: см. [тарифы CDN](https://cloud.yandex.ru/docs/cdn/pricing); калькулятор — отдельно от Object Storage.
- **Ожидаемый порядок:** при низкой посещаемости — по-прежнему близко к минимуму; при росте аудитории закладывать трафик, не ГБ в бакете.

### Сценарий C: сравнение с «только Timeweb»

Timeweb уже отдаёт `out/`; Object Storage имеет смысл для **единого публичного CDN медиа/JSON**, обновления расписания без полного ребилда и единого `NEXT_PUBLIC_S3_PUBLIC_BASE_URL`. Решение «остаёмся на Яндексе» для hot storage обычно оправдано при объёме **< 1–5 ГБ** и умеренном трафике.

## Рекомендация по классу и CDN

- Класс хранения: **Standard**.
- Для прод-домена с TLS: **Yandex CDN** → origin = бакет; `NEXT_PUBLIC_S3_PUBLIC_BASE_URL` = URL CDN (без завершающего `/`).
- JSON, обновляемые на месте: короткий `Cache-Control` или версия в пути (см. [static-hosting-s3-yandex.md](./static-hosting-s3-yandex.md)).

## Чеклист перед включением биллинга

- [ ] Пройти калькулятор с вашими ГБ, GET/PUT и ГБ egress.
- [ ] Зафиксировать выбранный сценарий (A или B) в execution-log или тикете.
- [ ] Настроить алерт бюджета в Yandex Cloud Billing (по желанию).
