# Решение по обработке заявок и обработчикам

**Дата фиксации:** 29 мая 2026  
**Статус:** действует до отдельного решения оператора

## Принцип локализации

Оператор обрабатывает и **хранит персональные данные только на серверах на территории Российской Федерации**.

Публичная политика на сайте ([`/legal/personal-data/`](../../apps/web/app/legal/personal-data/page.tsx)) отражает это правило.

## Целевая архитектура (продакшен)

| Компонент | Роль | Локализация |
|-----------|------|-------------|
| Yandex Cloud | Статический хостинг сайта, HTTP-приём и передача заявок (`bm-lead-receiver`) | РФ |
| Сервер Оператора | Журнал заявок, хранение ПДн | РФ |
| ООО «Яндекс» / Метрика | Веб-аналитика (после cookie-согласия) | РФ |

Персональные данные из заявок **официально** проходят через инфраструктуру Yandex Cloud и далее — на сервер Оператора в РФ. Иные каналы не используются для обработки ПДн в продакшене.

## Временный режим разработки (до публикации)

В тестовой среде [`apps/yandex-lead-receiver/`](../../apps/yandex-lead-receiver/) могут использоваться:

- **Google Sheets** — журнал заявок (временно);
- **Telegram** — операционные уведомления о новой заявке (временно).

Это **не** целевая продакшен-архитектура и **не** отражается в публичной политике.

**Перед публикацией сайта:**

1. Переключить `bm-lead-receiver` на сохранение заявок на **сервер Оператора в РФ** (без Google Sheets).
2. Убрать отправку заявок в **Telegram** из функции приёма заявок.
3. Не обрабатывать реальные ПДн посетителей через Sheets/Telegram в продакшене.
4. Обновить уведомление в Роскомнадзоре по [rkn-notification-checklist.md](./rkn-notification-checklist.md) (только Yandex Cloud, сервер в РФ, Метрика).

## Прочие решения

| Вопрос | Решение |
|--------|---------|
| Аналитика | Яндекс.Метрика — только после согласия в cookie-баннере; Вебвизор — при полном согласии на аналитику |
| Маркетинговые рассылки | Отдельное согласие; в форме заявки не запрашивается |
| Google Sheets (контент) | Отдельный контур: редактура каталога/расписания, не журнал заявок с ПДн |

## Действия оператора

1. Пройти [rkn-notification-checklist.md](./rkn-notification-checklist.md) (локализация только РФ).
2. Завершить миграцию lead-receiver с Sheets на сервер в РФ до приёма боевых заявок.
3. Ограничить доступ к журналу заявок (учётные записи, HTTPS, секреты в облаке).
