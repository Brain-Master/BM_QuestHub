## **1\. Executive Summary (Бизнес-задача и Психология)**

В сложных EdTech-продуктах статусы мероприятий (набор открыт, мест нет, отменено) выполняют критически важную роль. Они не просто информируют клиента, они **управляют его ожиданиями и направляют по воронке продаж**.

**Проблема неструктурированных данных:** Исторически сложилось так, что CRM-системы и бэкенд оперируют сухими, бюрократическими или техническими терминами («Согласование», «Архив», «Планируется»). Если выводить эти термины напрямую в клиентский интерфейс, мы неизбежно столкнемся с падением конверсии. Клиент не хочет разбираться во внутренних процессах компании. Слово «Согласование» вызывает у родителя тревогу («А состоится ли лагерь вообще?»), и он откладывает покупку.

**Наше решение (The Adapter Pattern):** Мы внедрили жесткое разделение между **Business Logic** (как данные хранятся в базе) и **Presentation Layer** (как клиент их воспринимает). На фронтенде работает специальный слой-адаптер (семантический транслятор), который перехватывает сырые данные (вместимость, даты, текстовые статусы из базы) и конвертирует их в человекопонятные, психологически выверенные триггеры, окрашенные в правильные цвета.

## **2\. Матрица Статусов (The Status Matrix)**

Ниже представлена полная таблица маппинга: от того, что приходит от API, до того, что видит конечный потребитель в карточке расписания.

### **2.1. 🟢 Активный набор (Default Success)**

* **Триггер (Backend):** Любое активное мероприятие по умолчанию (если нет конфликтов дат или лимита мест).  
* **UI Статус (Frontend):** Идёт набор  
* **Design Token (Цвет):** success (Изумрудный / Emerald 400).  
* **Микроинтеракция:** Дополняется пульсирующей зеленой точкой (animate-pulse), которая на подсознательном уровне сигнализирует о том, что процесс "живой" и актуальный.  
* **Поведение кнопки (CTA):** Кнопка активна, градиент от зеленого к бирюзовому. Текст: «Записаться».

### **2.2. 🔵 Стадия анонса (Pre-launch)**

* **Триггер (Backend):** status \=== 'Планируется' ИЛИ status \=== 'Согласование'.  
* **UI Статус (Frontend):** Скоро старт  
* **Design Token (Цвет):** info (Голубой / Cyan 400).  
* **UX Обоснование:** Мы избавляемся от пугающего слова "Согласование". "Скоро старт" создает эффект тизера (Anticipation).  
* **Поведение кнопки (CTA):** Кнопка синяя. Текст меняется на «Оставить заявку». Мы собираем ранний спрос (Pre-orders) еще до того, как открыты официальные продажи.

### **2.3. 🟣 Открытый донабор (Late Joiners)**

* **Триггер (Backend):** status \=== 'Можно присоединиться'.  
* **UI Статус (Frontend):** Можно присоединиться  
* **Design Token (Цвет):** purple (Пурпурный / Fuchsia 400).  
* **UX Обоснование:** Разработано специально для годовых кружков и абонементов, которые стартовали в сентябре, но куда можно влиться в ноябре. Снимает главный барьер родителя: *"Они уже учатся, мой ребенок отстал, пойдем в следующем году"*.  
* **Поведение кнопки (CTA):** Активна. Текст: «Записаться».

### **2.4. 🟠 Дефицит и Аншлаг (Scarcity & Sold Out)**

* **Триггер (Backend):** Автоматически вычисляется через математику: capacity.booked \>= capacity.total ИЛИ принудительный статус от менеджера status \=== 'Мест нет'.  
* **UI Статус (Frontend):** Мест нет  
* **Design Token (Цвет):** warning (Оранжевый / Orange 400).  
* **UX Обоснование:** Это мощный триггер FOMO (Fear Of Missing Out). Оранжевый цвет выбран намеренно (вместо красного), так как это не "ошибка", а сигнал повышенного внимания. Он повышает ценность путевок на соседние недели (социальное доказательство востребованности).  
* **Поведение кнопки (CTA):** Кнопка перекрашивается в оранжевый. Текст меняется на «В лист ожидания». Это критически важно для бизнеса — мы не теряем "горячего" клиента, а собираем базу для обзвона в случае отказов (отмен броней) других клиентов.

### **2.5. ⚪️ Авто-архивация (Smart Archiving)**

* **Триггер (Backend):** Алгоритм checkIsAutoArchived сопоставляет поле endDate (формат ISO) с текущей системной датой new Date().  
* **UI Статус (Frontend):** Завершено  
* **Design Token (Цвет):** default (Серый / Slate 400).  
* **UX Обоснование:** Снимает ручную нагрузку с контент-менеджеров. Мероприятия сами "затухают", когда их время прошло. Карточка визуально деградирует (применяется CSS-фильтр grayscale и opacity-60).  
* **Поведение кнопки (CTA):** Кнопка становится глухой серой (bg-slate-800), атрибут disabled={true} блокирует все клики. Защита от мусорных лидов в CRM.

### **2.6. 🔴 Принудительная отмена (Force Cancellation)**

* **Триггер (Backend):** status \=== 'Отменено'.  
* **UI Статус (Frontend):** Отменено  
* **Design Token (Цвет):** destructive (Красный / Red 400).  
* **UX Обоснование:** Используется для форс-мажоров. Карточка уходит в "серый" режим деградации, как и архив, но яркий красный бейдж информирует клиента о причине.  
* **Поведение кнопки (CTA):** Кнопка серая, disabled={true}, текст: «Отменено».

## **3\. Архитектура Адаптера (Как это работает в коде)**

Логика маппинга вынесена в чистые, чистые (pure) хелпер-функции. Это гарантирует, что изменение логики статусов не потребует переписывания тяжелых React-компонентов карточек.

### **Фаза 1: Определение состояния (The Truth Source)**

const getDisplayStatus \= (item) \=\> {  
  const isAutoArchived \= checkIsAutoArchived(item.endDate);  
  const isCancelled \= item.status \=== 'Отменено';  
  const isArchivedState \= item.isArchived || isAutoArchived || isCancelled;  
  const isSoldOut \= item.capacity.booked \>= item.capacity.total || item.status \=== 'Мест нет';  
  const isPlanning \= \['Планируется', 'Согласование'\].includes(item.status);  
  const isJoinable \= item.status \=== 'Можно присоединиться';

  // Иерархия возврата (порядок имеет значение\!)  
  if (isCancelled) return 'Отменено';  
  if (isArchivedState) return 'Завершено';  
  if (isJoinable) return 'Можно присоединиться';  
  if (isPlanning) return 'Скоро старт';  
  if (isSoldOut) return 'Мест нет';  
  return 'Идёт набор'; // Fallback / Default  
};

*Примечание для разработчиков: Порядок if-стейтментов (if-statements) критичен. Физически прошедшая смена (isArchivedState) не должна получать статус "Мест нет", даже если она была выкуплена на 100%. Приоритет времени выше приоритета вместимости.*

### **Фаза 2: Выбор токена дизайна (Color Mapping)**

const getStatusVariant \= (item) \=\> {  
  const status \= getDisplayStatus(item); // Используем уже отфильтрованный статус  
  if (status \=== 'Отменено') return 'destructive';  
  if (status \=== 'Завершено') return 'default';  
  if (status \=== 'Можно присоединиться') return 'purple';  
  if (status \=== 'Скоро старт') return 'info';  
  if (status \=== 'Мест нет') return 'warning';  
  return 'success';  
};

## **4\. Визуализация и Доступность (A11y & Contrast)**

Отображение бейджей поверх пользовательских изображений (UGC) — известная проблема UI-дизайна. Под бейджем может оказаться слепяще белый снег или черное ночное небо. Использование классических полупрозрачных плашек приведет к нарушению стандартов доступности (WCAG).

**UI Решение — Паттерн Solid Glow:**

* Мы используем компонент \<Badge variant={statusVariant} solid={true}\>.  
* Проп solid гарантирует, что фон бейджа принудительно заливается цветом bg-slate-900 (глубокий угольно-черный). Это создает идеальную контрастность (Contrast Ratio) для цветного текста.  
* Вокруг бейджа генерируется неоновая тень (shadow-\[0\_0\_8px\_rgba...\]) и обводка в цвет самого статуса.  
* **Результат:** Бейдж всегда читается на 100%, выглядит дорого и поддерживает общую эстетику Dark Mode.

## **5\. Внешние интеграции (mos.ru)**

Статус также влияет на маршрутизацию (Routing). Если в данных мероприятия присутствует поле mosRuLink (ссылка на запись через портал Госуслуг/Мос.ру), кнопка бронирования меняет свой приоритет:

* **Текст:** «На mos.ru»  
* **Иконка:** Меняется с шеврона на ExternalLink (квадрат со стрелочкой наружу), что обучает пользователя переходу на внешний ресурс.  
* **Экшен:** Отключает вызов внутренней формы BookingModal и вызывает открытие новой вкладки браузера.  
* *Важно:* Правила блокировки при этом сохраняются. Если смена с mos.ru находится в архиве, кнопка всё равно будет заблокирована.
